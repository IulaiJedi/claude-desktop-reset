# Спека: Claude Traffic Control (Windows)

21.11.2026. Требования оператора и согласованная архитектура. Аудит и источники —
`~/projects/teamlead/docs/research/2026-11-21-claude-traffic-control-audit.md` и
`…/2026-11-21-claude-set-i-telemetriya.md`.

## Цель и приоритеты

Свести к минимуму необязательную телеметрию и диагностику Anthropic, сохранив полную работу
Claude Code: вход, запросы, ответы, проекты, нужные API.
Приоритет 1 — работа Claude Code. 2 — прозрачность и обратимость. 3 — отключение
необязательного. Телеметрия и рабочие запросы могут идти через общую инфраструктуру — не
предполагать обратного.

## Требования оператора (кратко)

- Классы соединений: CORE, AUTH, TELEMETRY, DIAGNOSTICS, UPDATES, UNKNOWN; у каждого правила —
  источник и степень уверенности.
- Режимы: **SAFE CODE MODE** (официальные выключатели; Desktop и его фон — выключить;
  неизвестное не блокировать), **STRICT MODE** (только достоверно нужное; подтверждённая
  телеметрия — блок; неизвестное — в журнал на ручное решение; общий канал не блокировать),
  **RESTORE DEFAULTS** (снять свои правила, вернуть настройки; чужие правила и программы не трогать).
- Сначала официальные настройки; не отключать рабочие запросы под видом телеметрии; не менять
  содержимое запросов, не вмешиваться во вход; если категорию нельзя отделить — сказать прямо.
- Мониторинг: время, процесс, PID, адрес, домен (если достоверно), порт, протокол, класс,
  статус ALLOWED / BLOCKED / UNKNOWN. Без MITM и расшифровки; не заявлять, что читается
  содержимое HTTPS.
- Брандмауэр: без глобальных изменений; не блокировать весь Anthropic; не блокировать общий
  `node.exe`; без широких правил; понятные имена и описания; без дублей; полное удаление своих.
- Проверка после каждого режима: запуск, вход, тестовый запрос, ответ, доступность API,
  выключенная телеметрия (если поддерживается), отсутствие блокировки других программ.
  Статусы PROTECTED / PARTIALLY PROTECTED / NOT PROTECTED / ERROR; PROTECTED — только после
  фактической проверки; не обещать отсутствие телеметрии без доказательства.
- Карточка CLAUDE TRAFFIC CONTROL: режим, статусы Claude Code / Desktop / телеметрии, счётчики
  разрешённых / заблокированных / неизвестных, последняя проверка, последнее изменение; кнопки
  SAFE, STRICT, RESTORE, NETWORK AUDIT, VIEW LOGS; рабочие и необязательные соединения — раздельно.
- Файлы: `TrafficControl.ps1`, `NetworkMonitor.ps1`, `TelemetryManager.ps1`, `NetworkAudit.ps1`,
  `NetworkVerify.ps1`, `TrafficControl.log`, `Config`. Автономность; не ломать остальной инструмент.
- Безопасность: ничего скрытого; не менять IP, DNS, VPN, MAC, маршруты; не обходить вход; не
  удалять идентификаторы устройства; не трогать другие программы; всё обратимо; исходные значения
  сохранять до изменения; права администратора — только где нужны.
- **На машине разработчика ничего не применяется** — живой прогон делает оператор на другом устройстве.

## Согласованные решения (оператор, 21.11.2026: «хорошо» на рекомендации 1–4)

1. SAFE: официально выключаются отчёты об ошибках, `/feedback`, опросы; метрики Datadog —
   блок сетью; флаги функций сохраняются. STRICT: плюс официальный `DISABLE_TELEMETRY` с потерей
   функций, зависящих от флагов (список — в аудите, раздел 5).
2. Desktop: фон выключается (служба Cowork — «вручную»), сеть Desktop не блокируется; полный
   сетевой блок Desktop — отдельной кнопкой.
3. Проверка шлёт один тестовый запрос — с вопросом перед отправкой.
4. Карточка — экран в консольном меню ClaudeReset (пункт 10) и отдельный запуск `TrafficControl.cmd`.

## Что признано невыполнимым безопасно (сказано оператору)

- Разделить сетью собственную телеметрию Anthropic и рабочие запросы: один хост
  `api.anthropic.com` («Claude API requests… feature flag fetches, and telemetry event logging»).
- Белый список «только известное» для Claude Code: адреса меняются, MCP-серверы добавляет
  человек, в WSL брандмауэр не различает процессы. STRICT вместо этого = максимум официальных
  настроек + блок подтверждённой необязательной телеметрии + журнал неизвестного.

## Устройство

`windows/TrafficControl/`: модуль подключает ядро `ClaudeReset.ps1` (журнал, адаптер, защита
путей). Настройки — блок `env` в `settings.json` Windows и каждого WSL-дистрибутива; исходники и
состояние — `%LOCALAPPDATA%\ClaudeTrafficControl\Config`, журнал — там же. Правила брандмауэра —
группа «Claude Traffic Control»: по программе Claude Code (Windows) и правило Hyper-V для ВМ WSL.
Тесты — `windows/tests/TrafficControl.Tests.ps1`, только муляжи.
