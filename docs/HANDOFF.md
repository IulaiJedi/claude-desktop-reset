# Передача — claude-desktop-reset

## Бэклог — по первому аудиту с чужой машины (22.11.2026)

Отчёт `audit.cmd` прислали оператору 22.11. Сам отчёт в репозиторий не кладём: в нём имя
компьютера и профиль человека. Что в нём было: Desktop 5.11492 (MSIX), данные уже перенесены в
`%LOCALAPPDATA%\Claude-Data`, Desktop запущен, служба Cowork работает, запуск без администратора,
отдельного CLI нет (Code — вкладкой Desktop), Chrome и Яндекс открыты. Удаление по коду безопасно:
непустые папки не трогаются (`ClaudeReset.ps1:512`). Неверно только то, что человек читает:

1. Пункты «удалить, если опустеет» (`%LOCALAPPDATA%\Claude`, `Claude-Data`, `%PROGRAMDATA%\Claude`,
   `ClaudeReset.ps1:550–553`) получают размер всей папки (`:546`) и подпись «Пустая папка… не нужно
   для работы». В отчёте вышло «Пустая папка переноса данных — 682,8 МБ», а там все данные Desktop.
   Показывать 0 Б и подпись «удаляется, только если опустеет»; непустые в аудите не показывать
   (как `Get-CrResidue`, `:1280`). Отсюда же двойной счёт: итог раздела и «Уровень 3» завышены вдвое.
2. Кэши из `Partitions\*` есть в списке группы «Кэш», но не в её сумме (`:1583–1584`): 279,8 МБ в
   списке против 310,6 МБ у «Уровня 1», имена повторяются трижды. Считать их в кэше, из «Вход и
   веб-сессия» вычитать, имена давать без повторов.
3. «Claude Code попросит войти заново» стоит у каждого пункта следов входа (`:789`), в том числе у
   телеметрии и копий `.claude.json`. Последствие — своё на пункт.
4. Пустая строка «Версии:», когда CLI не найден (`:1518`).
5. Отчёт пишет «0.1.0», архив — v0.3 (`:32`, `linux/claude_reset.py:25`). Выровнять, выпуск — 0.3.1.
6. Браузер открыт → в аудите только «закройте и повторите» (`:1062`). Добавить, как закрыть до конца
   Chrome и Яндекс (работа в фоне, значок в трее) — как уже сделано для Edge (`:1487`).
7. Аудит без прав администратора при работающей службе Cowork молчит; предупреждение звучит только
   в момент чистки (`:1498`). Сказать в аудите: «для уровня 3 и чистки без следов — run.cmd от имени
   администратора; если Windows спросит пароль другой учётной записи, утилита увидит чужой профиль».
8. Новые имена в корне `Claude-Data\claude_pzs8sxrjxfjjc` у Desktop 5.11492: `ccd-ids.json`,
   `ccd-session-presets.json`, `claude-code-spare`, `Extension State`, `GPUPersistentCache`, `lockfile`,
   `plugin-list`, `remote-control-state.json`, `remote-file-download-parts.json`, `rpm`,
   `scratch-workspaces`, `ssh-remote-server-state.json`; в старом корне пакета — метка
   `.user-data-left.claude_pzs8sxrjxfjjc`. Сейчас это «Неизвестное» (только уровень 3) — так и
   оставить; `GPUPersistentCache` можно в кэш. Остальные — после живого просмотра.
9. Живой прогон пункта 5, шаг 4 (22.11): человек удалил данные claude.ai и anthropic.com в Chrome
   через «Все разрешения и данные сайтов», а повторная проверка всё равно пишет «Следы Claude в
   Local Storage». Похоже на ложное срабатывание: `Find-CrClaudeInFiles` (`:1036`) ищет ключ по
   байтам во всех файлах `Local Storage\leveldb`, а LevelDB при удалении дописывает пометку и
   держит старые записи в `.ldb`/`.log` до уплотнения. Не проверено на живом Chrome. Проверить:
   удалить данные сайта, закрыть браузер, прогнать детектор; если ловит — читать записи с учётом
   удалений или сменить текст на «если в настройках по слову claude пусто — это старые записи,
   браузер уберёт их сам». Тот же вопрос — у Session Storage и Service Worker (`:1096–1097`).
   Из отчёта той же чистки: Session Storage после ручного удаления пропал, Local Storage остался
   на четырёх проверках подряд, в том числе после перезапуска Chrome. Шаг 4 при этом печатает одну
   и ту же строку по нескольку раз, а «Chrome открыт» съедает один из пяти кругов (`:1716–1724`).
10. Ключ реестра, которого к моменту удаления уже нет, считается ошибкой (`:735`). В живом прогоне
    так вышло с двумя ключами `App Paths\claude-ssh-*.exe`: при планировании они были, а после
    удаления приложения (оно идёт первым) их уже не было — похоже, их убрала сама Windows. Две
    ложные «ошибки» дали итог «Сделано не всё». Нет ключа — статус «уже нет», не ошибка.
11. Мелкое: при Code только внутри Desktop (CLI не найден) `claude auth logout` не попадает в план
    (`:1265–1266`), хотя `Invoke-CrClaudeLogout` умеет взять встроенный `claude.exe` (`:878–881`) —
    этот запасной путь недостижим. В этом прогоне вреда не было: файла входа CLI нет, данные
    Desktop удалены целиком.

**Живой прогон пункта 5 на чужой машине (22.11), впервые по-настоящему:** удалено 22 пункта,
освобождено 701,2 МБ (план обещал 1,5 ГБ — пункт 1–2 выше); отработали удаление пакета
`Remove-AppxPackage`, ключи реестра HKCU, 30 записей куки Chrome через winsqlite3, папка IndexedDB
claude.ai, правка `.claude.json`, копии `.claude.json`, остаток папки пакета (172,5 МБ). Сверка
Claude Code до/после предупреждений не дала. Остались строка Local Storage (пункт 9) и две ложные
ошибки реестра (пункт 10). Служба Cowork и брандмауэр отдельно не проверялись.

Тесты: на муляже сверять цифры отчёта — сумма разделов равна итогу, «пустая» папка — 0 Б, у пункта
размер только своего. Сейчас тесты проверяют удаление, но не отчёт, поэтому 1–3 проскочили.
