## 1. macOS — Claude Desktop

- Установка: `.dmg` с claude.com/download, «Drag **Claude.app** to Applications» [A5 «Install the app»]; запуск из Applications, macOS 13+ [A2]. Официальной инструкции удаления / сброса для macOS — **не документировано** (в [A2] её нет).
- ⚠ Каталог данных: `~/Library/Application Support/Claude` [A3 «Where Cowork stores data»]. `claude_desktop_config.json` — `~/Library/Application Support/Claude/claude_desktop_config.json`, открывается Settings → Developer → Edit Config [A1 «Installing the Filesystem Server», шаг 2]. Логи MCP — `~/Library/Logs/Claude` (`mcp.log`, `mcp-server-SERVERNAME.log`) [A1 «Getting logs from Claude Desktop»]. Это совпадает с поведением Electron: `userData` = `~/Library/Application Support` + имя приложения, логи по умолчанию `~/Library/Logs/YourAppName` [E1 «app.getPath(name)», «app.setAppLogsPath»].
- Внутри каталога данных [A3 «Where Cowork stores data», таблица, «isn't a complete list»]: `local-agent-mode-sessions` — по папке на задачу Cowork плюс память и плагины Cowork; `vm_bundles` — образы диска VM. Бинарник Claude Code для вкладки Code: `~/Library/Application Support/Claude/claude-code/<version>/<build-id>/claude.app/Contents/MacOS/claude`, Team ID `Q6L2SF6YDW`, Signing ID `com.anthropic.claude-code` [A5 «Endpoint security software»: путь дан для `Claude-3p`, «Standard (non-3P) installs use `~/Library/Application Support/Claude/` with the same subpath»].
- Режим 3P держит отдельные каталоги: данные `~/Library/Application Support/Claude-3p/`, логи `~/Library/Logs/Claude-3p/` [A4 «Where data lives»]; там же `ant-did` (случайный идентификатор устройства), `configLibrary/`, файл `reset-app-data` — «makes the app delete the user's chats and other data at its next launch» [A4 «Identity», «Copy the data to the new device»]. Для стандартного каталога эти имена — **похоже** те же, прямо не документировано.
- Папка файлов Cowork — `~/Claude` по умолчанию, на части машин `~/Documents/Claude`; путь виден в Settings → Cowork; при удалении каталога данных **не удаляется** [A3; A4 «Where data lives»]. Это файлы пользователя — по задаче не трогать.
- Политики: preference domain `com.anthropic.claudefordesktop` [C1 «Device management policies»]; управляемые профили — `/Library/Managed Preferences/com.anthropic.claudefordesktop.plist` и `/Library/Managed Preferences/<user>/…plist` [A6, таблица источников]. Что это и bundle id приложения — **похоже**, Anthropic называет его только «preference domain». Путь пользовательского plist (`~/Library/Preferences/…`) — **не документировано**; Apple: в `Preferences` файлы руками не создают, только через `NSUserDefaults` [P2 «Library directory», строка Preferences].
- Keychain: элемент **«Claude Safe Storage»** назван Anthropic — после его удаления из связки или сброса login keychain сохранённые API-ключи 3P становятся нечитаемы [A4 «Unreadable saved API keys»]. `safeStorage` Electron на macOS: ключи «stored for your app in Keychain Access», другие приложения не читают их «without user override» [E2 «Platform-Specific Key Providers»]. Где Desktop хранит сам вход в claude.ai на macOS — **не документировано** (для Linux сказано прямо, см. §3).
- Входы в серверы плагинов вне вкладки Code: на macOS — login keychain (или файл, если связка отказала); ⚠ «stay in the login keychain after you delete the application-data directory», завершать — отключением сервера или отзывом на его сервере авторизации [A4 «Credentials», «Removing data»]. Переменные локального окружения Desktop «stored encrypted on your machine», где — не сказано [C1 «Use the local environment editor»].
- Встроенный браузер Desktop: «Sign-ins and cookies from the pane stay in the app's own browser storage on the device»; Cowork держит их до **Clear browsing data** в меню панели, Code — до выхода из приложения, если не включено **Keep cookies** [A7 «Built-in browser»].
- `claude://`: Desktop обрабатывает собственные ссылки `claude://` (пример `claude://code/new?...`) [C10 «Open a Claude Desktop session on an SSH connection»; C1 «Open an SSH session from a link»]. У Electron на macOS схема регистрируется только из `Info.plist` приложения; проверить можно по `~/Library/Preferences/com.apple.LaunchServices.plist` [E1 «app.setAsDefaultProtocolClient»]. Как именно регистрирует Claude — **не документировано**.
- Login items / LaunchAgents у Claude Desktop — **не документировано**. Механизм Electron: `app.setLoginItemSettings`, на macOS типы `mainAppService` (по умолчанию), `agentService` (plist в `Contents/Library/LaunchAgents` приложения), `daemonService`, `loginItemService` [E1 «app.setLoginItemSettings»]. Убрать вручную: System Settings → General → Login Items & Extensions, выбрать и Remove [P3].
- `~/Library/Caches/<…>`, `Saved Application State`, `HTTPStorages`, `WebKit` для Claude — **не документировано**. Apple описывает `Caches` как регенерируемые данные [P2], два остальных каталога в [P2] не названы. Правило Chromium `~/Library/Caches` + относительный путь профиля [G1 «User Cache Directory»] описано для Chrome; применяет ли его Electron — не документировано.
- Native messaging host Desktop для Claude in Chrome — **не документировано** (имя и путь — только в «Зацепках»). Подключение со стороны пользователя: в Desktop Settings → Customize → Connectors → Claude in Chrome [A10, пересказ].
- Выход: выход из Desktop данные Cowork не удаляет — «neither does signing out of Claude Desktop» [A3 «Offboard a member»]. При ошибках 403 во вкладке Code совет — выйти и войти из меню приложения, при необходимости полностью закрыть Desktop [C1 «403 or authentication errors in the Code tab»].

## 2. macOS — Claude Code

- ⚠ Учётные данные: «stored in the encrypted macOS Keychain»; если связка отказывает в записи (заблокирована в SSH и т. п.), вход пишется в `~/.claude/.credentials.json` с правами `0600` [C4 «Credential management»]; конкретно login keychain [C6 «Not logged in or token expired»]. ⚠ При `CLAUDE_CONFIG_DIR` запись Keychain «keyed» к этому каталогу — у разных каталогов разные записи [C4 там же]. **Имя элемента Keychain — не документировано.** Диагностика: `claude doctor` («macOS Keychain is not writable»), разблокировка `security unlock-keychain ~/Library/Keychains/login.keychain-db` [C6 там же].
- `/logout`: ⚠ «Logging out removes all stored credentials, including the plaintext file's contents, saved MCP server logins, and plugin sensitive values» [C6 «Not logged in or token expired», шаг 4]; сбрасывает состояние первого запуска [C4 «Log in to Claude Code»]; удаляет `~/.claude/remote-settings.json`, `policy-limits.json` и его `.stamp.json` [C7 «Kept until you delete them»]. CLI-аналог — `claude auth logout`; `claude auth status` (JSON, код выхода 0/1, поле `configDirectory`) [C12]. В таблице команд `/logout` — «Sign out from your Anthropic account», про отзыв на сервере ни слова [C11].
- Вход в Console без API-ключа хранится **вне** каталога конфигурации — профиль Anthropic в `~/.config/anthropic` (macOS и Linux); снимается `/logout` или `ant auth logout`, либо удалением файла профиля из `configs/` [C4 «Sign in without an API key», «Anthropic profiles and federation credentials»].
- Остальные следы входа: `~/.claude.json` — «account details», доверие проектам, MCP, UI [C7 «~/.claude.json»]; ключи в окружении — `ANTHROPIC_API_KEY` в `~/.zshrc`, `~/.bashrc`, `~/.profile` [C6 «This organization has been disabled…»]; `CLAUDE_CODE_OAUTH_TOKEN` (годовой токен `claude setup-token`, нигде не сохраняется) — убрать из профиля shell и из `env` в settings [C4 «Authentication precedence», «Generate a long-lived token»]. Секреты MCP OAuth: «system keychain (macOS) or a credentials file» [C13 «Use pre-configured OAuth credentials»]; «Clear authentication» в `/mcp` — «to revoke access» [C13 «Authenticate with remote MCP servers»].
- Установка (macOS и Linux одинаково): нативная — `~/.local/bin/claude` (симлинк) → `~/.local/share/claude/versions/` [C5 «Auto-updates»]; служебные `~/.claude/downloads/`, `~/.local/state/claude/` (lock-файлы), `~/.cache/claude/` (staged downloads), метод установки пишется в `~/.claude.json`; уважаются `XDG_DATA_HOME`, `XDG_STATE_HOME`, `XDG_CACHE_HOME` [C6 «Check directory permissions»]. Homebrew: casks `claude-code` и `claude-code@latest`; npm `@anthropic-ai/claude-code`; legacy `~/.claude/local/` [C5 «Install Claude Code»; C6 «Check for conflicting installations»].
- ⚠ Удаление [C5 «Uninstall Claude Code»]: `rm -f ~/.local/bin/claude; rm -rf ~/.local/share/claude`; `brew uninstall --cask claude-code[@latest]`; `npm uninstall -g @anthropic-ai/claude-code`; «Remove configuration files» — `rm -rf ~/.claude; rm ~/.claude.json` и в проекте `.claude`, `.mcp.json` («delete all your settings, allowed tools, MCP server configurations, and session history»). VS Code, JetBrains и Desktop тоже пишут в `~/.claude/` и пересоздают его. Про очистку Keychain в инструкции удаления — ни слова.
- Прочие локальные следы: обработчик `claude-cli://` — `~/Applications/Claude Code URL Handler.app` (macOS), `claude-code-url-handler.desktop` в `$XDG_DATA_HOME/applications` (Linux), регистрируется при первом сообщении в интерактивной сессии, запрет — `disableDeepLinkRegistration` [C10 «Registration and supported platforms»]. Scratchpad — `/private/tmp/claude-<uid>/…` (macOS), `/tmp/claude-<uid>/…` или `$TMPDIR` (Linux) [C7 «Session scratchpad directory»]. В глобальный git excludes дописывается `**/.claude/settings.local.json` [C14] — чужой файл, не трогать.

## 3. Linux (Ubuntu, WSL2)

**Claude Desktop для Linux — есть официально, в бета-версии.** «Linux support for the Claude desktop app is in beta»; Ubuntu 22.04+ или Debian 12+, x86_64/arm64; Fedora/Arch — только CLI [C2 «Requirements»]; то же в [A2] и [C1] («Get Claude for Linux (beta)»).
- Установка: apt-репозиторий `https://downloads.claude.ai/claude-desktop/apt/stable`, ключ `/usr/share/keyrings/claude-desktop-archive-keyring.asc`, список `/etc/apt/sources.list.d/claude-desktop.list`, пакет `claude-desktop`, команда `claude-desktop`; сам не обновляется [C2 «Install», «Update»]. Удаление: `sudo apt remove claude-desktop` снимает и запись репозитория с ключом; вручную добавленный `.list` удалить отдельно [C2 «Uninstall»]. Про пользовательские данные при удалении — **ни слова**.
- Данные: `~/.config/Claude/claude_desktop_config.json`, логи `~/.config/Claude/logs` [A1]; режим 3P — `~/.config/Claude-3p/` [A4 «Where data lives»]. Electron: `appData` на Linux = `$XDG_CONFIG_HOME` или `~/.config` [E1]. `~/.cache/Claude` — **не документировано**.
- ⚠ **Вход Desktop на Linux хранится в keyring рабочего стола**: «Claude Desktop saves your sign-in in your desktop's keyring, such as GNOME Keyring or KDE Wallet»; без разблокированного keyring вход не сохраняется [C2 «Your sign-in won't be saved on this device»]. Имя элемента — **не документировано**. Electron на Linux: `gnome_libsecret`, `kwallet*`, без хранилища — `basic_text`; выбор по рабочему столу, переопределяется `--password-store` [E2 «getSelectedStorageBackend»]. Ключ GNOME Keyring не расшифровывается в KDE и наоборот [A4 «Unreadable saved API keys»]. Входы в серверы плагинов на Linux — незашифрованный `.credentials.json` под `plugin-mcp-auth/` или `connectors/*/plugin-mcp/` [A4 «Credentials»].
- Политика Desktop на Linux — root-файл `/etc/claude-desktop/managed-settings.json` (не путать с managed settings Claude Code) [C1 «Device management policies»; A6]. Cowork на Linux — VM на QEMU/KVM, нужен доступ к `/dev/kvm`, `/dev/vhost-vsock` [C2 «Cowork requirements»]; где лежат образы VM на Linux — **не документировано** ([A3] даёт только macOS и Windows). Регистрация `claude://` на Linux — **не документировано**.
- **Claude Code на Linux:** ⚠ «credentials are stored in `~/.claude/.credentials.json` with file mode `0600`» — файл, не libsecret [C4 «Credential management»]. Пути установки, XDG-каталоги, удаление — как в §2 (общие для «macOS, Linux, WSL»); apt/dnf/apk: `claude-code`, `/etc/apt/sources.list.d/claude-code.list`, `/etc/apt/keyrings/claude-code.asc` [C5 «Uninstall with apt, dnf, or apk»]. `~/.config/claude` и прочие XDG-каталоги, кроме названных в §2, — не упоминаются.
- **WSL2:** ставится Linux-установщиком внутри дистрибутива [C5 «Install in WSL»]. Вход: если браузер не открылся или упал на `localhost`, — `c` копирует URL, вход в браузере Windows, код вставляется в `Paste code here` или через `claude auth login`; можно указать браузер Windows: `export BROWSER="/mnt/c/Program Files/Google/Chrome/Application/chrome.exe"` [C6 «OAuth login fails in WSL2, SSH, or containers»]. `wslview` в документации **не упоминается**; `xdg-open` в WSL часто отсутствует (`xdg-utils`) [C10 «xdg-open is not found on Linux»]. Вывод: при входе из WSL cookies claude.ai остаются в браузере **Windows**. Claude in Chrome в WSL **не поддерживается** [C9, примечание вверху]. Desktop для Windows умеет Code-сессии внутри WSL 2 (WSL 1 нет) [C3 «Requirements»]; где такая сессия хранит вход — **не документировано**. Импорт MCP из Desktop работает только на macOS и WSL [C13 «Import MCP servers from Claude Desktop»].

## 4. Домены входа и завершение сессий на сервере

- Claude Code [C8 «Network access requirements»]: `claude.ai` — «claude.ai account authentication»; `claude.com` — вход «opens a `claude.com` page in the browser, which redirects to `claude.ai`»; ⚠ `platform.claude.com` — вход в Console, и «OAuth token exchange, refresh, and revocation also go to this host for claude.ai accounts»; `sso.claude.com` — SSO; `api.anthropic.com` — API; `bridge.claudeusercontent.com` — мост Claude in Chrome; `downloads.claude.ai` — установщик.
- Desktop [C1 «Network access requirements»]: `anthropic.com`, `*.anthropic.com`, `claude.ai`, `*.claude.ai`, `claude.com`, `*.claude.com`, `claude.app`, `*.claude.app`, `*.claudeusercontent.com`, `*.claudemcpcontent.com`; узкий список: `a-api.anthropic.com`, `a.claude.ai`, `assets.claude.ai`, `platform.claude.com`, `sso.claude.com` и др. Какие из них ставят cookies входа — **не документировано**. `console.anthropic.com` в текущих документах не встретился.
- ⚠ **Выйти везде:** claude.ai в браузере → Settings → Account → **Log Out** — немедленный выход на всех устройствах: веб, мобильные, десктоп, Claude Code (включая токены `setup-token`), Claude in Chrome и др.; на iOS/Android этой кнопки нет; API-ключи не затрагивает [A8]. Только Claude Code: удалить его токен — в Settings → Account или Settings → Claude Code, значок корзины [A8]. Отдельные сеансы: Settings → Account → Active sessions («Where you're logged in») → ⋯ → **Terminate** [A9].
- API-ключи Console: platform.claude.com/settings/keys; **Disable** обратим, **Delete** окончателен (ключ архивируется) [A11 «Create and use a key»].
- ⚠ **Отзывает ли удаление локальных токенов их на сервере — не документировано.** Документировано рядом: `/logout` «removes and revokes» — только для входа в Console без ключа [C4 «Sign in without an API key»]; для claude.ai-входа CLI лишь известно, что запросы отзыва идут на `platform.claude.com` [C8], без указания, что их шлёт `/logout`. Для Desktop: удаление каталога данных входы в серверы плагинов **не** отзывает [A4 «Removing data»], смена режима «doesn't revoke» [A4 «Data shared…»]. Надёжный путь по документам — серверный выход [A8]/[A9] **до** локальной чистки.

## 5. Браузеры

**Где профили.** Chrome: macOS `~/Library/Application Support/Google/Chrome`, Linux `~/.config/google-chrome` (beta/unstable/canary — свои), Chromium `~/.config/chromium`; Linux переопределяется `$CHROME_CONFIG_HOME`/`$XDG_CONFIG_HOME`, `--user-data-dir`, `$CHROME_USER_DATA_DIR`; профиль — подкаталог (`Default`); путь — `chrome://version` → Profile Path; кэш: macOS `~/Library/Caches/Google/Chrome/Default`, Linux `~/.cache/google-chrome/Default` [G1 «Current Location», «Default Location», «User Cache Directory», «Overriding the User Data Directory»]. Edge: каталог данных = родитель `NativeMessagingHosts` — macOS `~/Library/Application Support/Microsoft Edge[ {Channel}]`, Linux `~/.config/microsoft-edge` [M1 «Step 3»]. Brave: только macOS `~/Library/Application Support/BraveSoftware/Brave-Browser/` [C9 «Extension not detected»]; Linux/Windows — **не документировано** в проверенных источниках. Firefox: корень профилей macOS `~/Library/Application Support/Firefox/Profiles`, Linux `~/.mozilla/firefox`, Windows `%APPDATA%\Mozilla\Firefox\Profiles`; кэш — `~/Library/Caches/Firefox/Profiles`, `~/.cache/mozilla/firefox`, `%LOCALAPPDATA%\Mozilla\Firefox\Profiles` — «caches that can safely be deleted» [F1]. Safari — пути на диске **не документировано**.

**Хранилища по сайту (Chromium, по исходнику — это код, не документация):**
- Cookies — SQLite `Network/Cookies` [G7]; таблица `cookies` с колонками `host_key`, `top_frame_site_key`, `name`, `value`, `encrypted_value`… и уникальным индексом по `host_key` [G4]. Шифрование на macOS/Linux — см. `safeStorage` выше (для Chrome — **похоже**, не проверено).
- Local Storage — **одна** база на раздел хранения: `Local Storage/leveldb`, а в новой схеме SQLite — `LocalStorage`; Session Storage — `Session Storage` / `SessionStorage` [G8]. Вывод: данные всех сайтов в одной базе, удалить «папку сайта» нельзя.
- Каталоги раздела: `IndexedDB`, `Service Worker`, `CacheStorage`, `ScriptCache`, `WebStorage` (storage buckets), `FileSystem`, `BackgroundFetch` [G9]; раскладка по origin внутри — **не документировано**.
- Расширения: `Extensions`, `Local Extension Settings`, `Sync Extension Settings`, `Extension State` [G10].
- Firefox: всё хранилище квот — `<profile>/storage`, данные сайтов — `<profile>/storage/default`; «Les utilisateurs ne doivent pas ajouter leurs propres répertoires ou fichiers sous `<profile>/storage`» [F3 «Où sont stockées les données ?»]. Имя `cookies.sqlite` — ⚠ только по поисковой выдаче к статье SUMO, первоисточником не подтверждено.

**Можно ли править базу cookies при запущенном браузере — не документировано.** По коду Chrome: база cookies открывается с `set_exclusive_locking(false)`, а запрет открытия файла чужим процессом — только на Windows (`exclusive_cookie_database_locking`) [G5]; блокировки SQLite кооперативные, «does not protect the database file from uncooperative processes» [G6]. Подхватит ли браузер правку или перезапишет её — не описано. Вывод: чистить при закрытом браузере или через его UI.

**Официальный UI «удалить данные одного сайта»:**
- Chrome: ⋮ → Settings → Privacy and security → Third-party cookies → See all site data and permissions → найти сайт → Delete; «If you delete cookies, you may get signed out of sites» [G3 «Delete specific cookies»]. `chrome://settings/content/all` в справке не назван.
- Edge: Settings → Privacy, search, and services → Cookies → See all cookies and site data → сайт → Delete [M2 «Delete cookies from a specific site»].
- Firefox: значок замка → Clear cookies and site data; или Settings → Privacy & Security → Cookies and Site Data → Manage Data [F2, ⚠ по выдаче].
- Safari: Safari → Settings → Privacy → Manage Website Data → выбрать сайт → Remove; «may also sign you out», и удаление «may change or remove them in other apps» [P1].
- Brave: **не документировано** в проверенных источниках.

**Политики и флаги.** По сайту — только `CookiesSessionOnlyForUrls` (шаблоны URL, cookies живут одну сессию; Chrome 11+) [G11]. `BrowsingDataLifetime` (Chrome 89+) и `ClearBrowsingDataOnExitList` (Chrome 89+) работают по типам данных, не по сайтам, и сохраняют вход в Google-аккаунт; `ClearSiteDataOnExit` снят в Chrome 29 [G11]. Ключа командной строки «очистить данные сайта» — **не документировано**. `Clear-Site-Data` — заголовок **ответа сервера** (`"cookies"` чистит весь зарегистрированный домен с поддоменами), локально не применить [F4].

**Claude in Chrome.**
- Магазин: https://chromewebstore.google.com/detail/claude/fcoeoabgfenejglbffodgkkbkcdhcgfn, ID `fcoeoabgfenejglbffodgkkbkcdhcgfn` [C9 «Prerequisites»; A10]. ⚠ Браузеры по-разному: [A10] — только Chrome; [C9] — Chrome и Edge, плюс Brave, Arc, Vivaldi, Opera; [A7 «Set up Claude in Chrome on a device»] — Chrome или Edge на macOS или Windows.
- Host Claude Code — `com.anthropic.claude_code_browser_extension`, файл ставится при первом включении интеграции: Chrome — macOS `~/Library/Application Support/Google/Chrome/NativeMessagingHosts/…json`, Linux `~/.config/google-chrome/NativeMessagingHosts/…json`, Windows `HKCU\Software\Google\Chrome\NativeMessagingHosts\`; Edge — `~/Library/Application Support/Microsoft Edge/NativeMessagingHosts/`, `~/.config/microsoft-edge/NativeMessagingHosts/`, `HKCU\Software\Microsoft\Edge\NativeMessagingHosts\`; остальные Chromium — свой каталог конфигурации, Brave на Windows — `HKCU\Software\BraveSoftware\Brave-Browser\NativeMessagingHosts\` [C9 «Extension not detected»]. Host Desktop `com.anthropic.claude_browser_extension` — **не документировано** (см. «Зацепки»).
- Общие места хостов: Chrome — системные `/Library/Google/Chrome/NativeMessagingHosts/`, `/etc/opt/chrome/native-messaging-hosts/`, Chromium — `/Library/Application Support/Chromium/…`, `/etc/chromium/…`, `~/.config/chromium/NativeMessagingHosts/`; Windows — `HKCU|HKLM\SOFTWARE\Google\Chrome\NativeMessagingHosts\<name>` [G2 «Native messaging host location»]. Edge: `/Library/Microsoft/Edge/NativeMessagingHosts/`, `/etc/opt/edge/native-messaging-hosts`; ⚠ на Windows Edge при отсутствии своих ключей читает ключи Chromium и Chrome [M1 «Step 3»].
- ⚠ «If you log out of the extension, you lose the shortcuts and scheduled tasks saved in it» [C9 «Extension signed in to a different organization»]. Удалятся ли вход расширения вместе с данными сайта claude.ai — **не документировано**.

## Чего в первоисточниках нет

- **macOS Desktop:** инструкция удаления/сброса; путь пользовательского plist и прямое «bundle id = `com.anthropic.claudefordesktop`»; `~/Library/Caches/…`, `Saved Application State`, `HTTPStorages`, `WebKit` для Claude; login items / LaunchAgents; где хранится вход в claude.ai (кроме общего «Claude Safe Storage» для ключей 3P); как регистрируется `claude://`; native host Desktop для Claude in Chrome.
- **Claude Code:** имя элемента Keychain на macOS; отзывает ли `/logout` claude.ai-токен на сервере (явно — только для Console без ключа); точные поля учётной записи в `~/.claude.json`.
- **Linux:** имя записи Desktop в GNOME Keyring / KWallet; `~/.cache/Claude`; место образов VM Cowork; регистрация `claude://`; судьба `~/.config/Claude` после `apt remove`; Desktop-сессия в WSL — где её вход; `wslview`.
- **Сервер:** инвалидирует ли удаление локальных токенов (Desktop, CLI, браузер) их на сервере; какие домены из списков несут cookies входа; `console.anthropic.com` в текущих документах нет.
- **Браузеры:** Brave — пути и UI; Safari — пути на диске; раскладка IndexedDB/Service Worker по origin; поведение при правке `Cookies` на ходу; где расширение Claude in Chrome хранит свой вход; Firefox — статьи SUMO не открылись автоматически, `cookies.sqlite` не подтверждён.
